
正文：
```
日常选 API 的时候发现同一个模型在不同平台价格差异很大，就顺手做了个工具。

做法很简单：把 673 个模型的快照按家族（DeepSeek / Qwen / GLM / Kimi 等）分组，每 12 小时自动同步一次，按输入价排序标出最便宜的调用渠道。数据源是 OpenRouter、LiteLLM、Epoch 这些公开源，价格统一换算成美元 / 百万 token。

几个实现上的坑：
- 上游价格格式不统一：有 $/token 的字符串、有科学计数法、有浮点尾巴，都得在管线里归一化
- 同一家族里 OCR、音频这类专用端点价格往往最低，放进同一张榜会把「最低」标给非对话模型，所以单独排除了
- 模型退役、上新都在快照里体现，页面不需要人工维护

地址：https://aimodle.cn/welfare

页面上还有一页返佣福利榜，每条标了复核日期，活动结束就下架。欢迎挑数据错误，价格抓错了我会修。
```

## 掘金长文（注册后发）

标题：
```
我如何用定时管线维护一个 673 模型的 AI 价格雷达
```

大纲：
1. 动机：同一模型跨平台差价数倍，选型时要手动比价
2. 数据源选择标准：必须有统一模型注册表才能自动化（models.dev / OpenRouter / LiteLLM / Epoch）
3. 价格归一化的坑：$/token 字符串、5E-7 科学计数法、浮点尾巴（2e-7×1e6=0.19999999999999998）
4. 家族分组与端点排除：为什么 OCR/音频端点不能和对话模型同榜
5. 零维护架构：GitHub Actions 每 12h 同步 + 快照 diff 生成变更日志 + RSS
6. 效果与限制：673 模型 / 73 厂商，哪些数据缺失（价格覆盖约 90%）
7. 文末放站点链接 + 仓库链接
