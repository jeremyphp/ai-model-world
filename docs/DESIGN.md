# 大模型世界 · 视觉设计规格

这份文档是「模型属性 → 人物形象」的完整对照表，**供人工核对用**。
每一条视觉表现都必须能追溯到一个具体的数据字段和一个具体的数据源；
任何找不到数据支撑的视觉元素都不允许存在，任何拿不到数据的情况都必须有明确的兜底表现。

配套文档：数据来源与仲裁规则见 [DATA.md](./DATA.md)，系统架构见 [ARCHITECTURE.md](./ARCHITECTURE.md)。

## 一、世界观

整个网站是一个王者荣耀风格的像素峡谷，每个大语言模型是这个世界里的一位英雄——
披金边披风、肩甲与金腰带，踩着金色光环，手握各自的看家武器。

世界分为两片，用的是读者一秒就懂的词，而不是自造的地名：

| 区域 | 归属 | 建筑风格 |
|---|---|---|
| **国内** | 总部在中国大陆、香港、澳门、台湾的厂商 | 飞檐、红墙、竹林、灯笼 |
| **国外** | 其余所有国家（含日、韩、新、印） | 玻璃幕墙、摩天楼、霓虹 |

> 第一版叫「西岸都会 / 东方城邦」，并把日韩新印都归到「东方」。用户反馈直接：
> 「应该改为国外这种更直接易懂的」。**地名是给世界观加分的，不能给理解加成本**——
> 一个词如果需要解释，就换掉它。同理全站的「居民 / 户人家 / 庄园 / 往生堂」
> 都换成了「模型 / 家 / 全部模型 / 已退役」。

归属由厂商总部所在国自动推导，规则见 `src/data/vendor-registry.ts` 的 `continentForCountry()`
（管线侧 `scripts/sync/merge/vendor-registry.ts` 有同一份国家清单）。
前端读快照时会按注册表**重算**每家厂商的归属，而不信快照里写死的旧值——
规则改动后不需要等管线下一次运行才生效。新厂商出现时无需人工干预即可正确归位。

**开源与闭源不用地理区分**，而是用居所形态表达：开源模型的房子没有围墙、大门敞开；
闭源模型的房子有围墙和门禁。

## 二、界面结构：村落里的小屋

### 2.0 一次失败的方案，以及为什么改

第一版把角色做成了「排排站」：所有属性都压在 64×64 的像素小人身上，
按观看距离分成远景 / 悬停卡 / 详情页三层投放。

**这个方案失败了。** 用户的原话是「人物之间的特征区别不太明显，
没办法直观地感受到各个模型之间的区别到底在哪里」。

根因是 64 像素这个分辨率根本承载不了「谁会写代码」这种信息——
眼镜、耳机、腰带在远景里都只有几个像素点，堆十个信号的结果是哪个都不醒目。
而最能区分模型的那些事（编程能力、记忆长度）被藏进了需要点击才能看到的详情页。

### 2.0b 第二次失败：把数据编码进画里，本身就是错的

小屋方案上线后问题依旧。反馈是「读者并不能直观地看到每个模型的特点，
还是有很大的理解成本」。

这一次的根因比上一次深：**隐喻不是图形，是密码。** 「书架高度 = 上下文窗口」
这条规则要成立，读者必须先看图例、记住它、再回到画面上解码。没有人会这么做。

实测数据把问题量化了（广场 39 间屋）：

| 现象 | 出现率 | 后果 |
|---|---|---|
| 桌上是同一张问号盖布桌 | 79% | 屋内右侧三分之一，全场传递 0 bit 差异 |
| 角色披着雾化斗篷 | 77% | 「参数量未公开」退化成默认皮肤 |
| 书架落在顶两档 | 59% | 高度在旗舰之间几乎不可分 |
| 名牌写「未参赛」 | 69% | 名次这个最强抓手，七成屋子没有 |
| 挂着「会用工具」图标 | 74% | 满屏都有等于没有 |

十个视觉编码维度里有六个在缩略尺寸下读不出来。
更糟的是**当 79% 的屋子摆着同一张问号桌时，读者会把它读成一件普通家具，
而不是一个「缺数据」的警告**——稀有的警告才是警告。

### 2.1 现在的结构：画归画，数归数

**宝可梦图鉴不会因为喷火龙血厚就把它画大一圈，它在旁边画一根条。**
FIFA 球星卡也一样：左上角一个总评数字，底下一行属性，人像只负责「这是谁」。
这两个「让上亿人一眼看懂角色特点」的成功案例，在有完整数据的情况下
都选择了条形而不是把数据编码进画面。

所以现在的分工是：**房间与角色负责身份与观感，四条能力横条负责比较。**

```
┌──────────────────────────┐  屋顶：厂商品牌色，东西方檐口形制不同
│ 2026.06                  │  门楣匾额：出生年月
│  📚      🧍       💻     │  书架与电脑降为场景陈设（见下）
│ ════════════════════════ │  地板
├──────────────────────────┤
│ [全球最强] [编程好手]    │  自动特征标签，1~3 块
│ Claude Fable 5           │  模型名
│ 🐋 Anthropic      👁🔧  │  家徽 + 厂商 + 能力图标
│ 聪明 ▮▮▮▮▮▮▮▮  世界#1   │  ← 四条能力横条：这是主要信息通道
│ 编程 ▮▮▮▮▮▮▮▯  顶尖     │
│ 记性 ▮▮▮▮▮▮▮▮  1M       │
│ 便宜 ▮▯▯▯▯▯▯▯  $50      │
│ 全世界综合智力最强的模型  │  ← 一句话人设，见第 4.5 节
└──────────────────────────┘
```

横条是零学习成本的：不用查图例，谁的格子多谁就强。缺数据的画成**带描边的空槽**，
与「填了 0 格」在视觉上截然不同——「没测过」和「得了零分」必须一眼可辨。

四条的取值规则见 `src/lib/aptitude.ts`：

| 条 | 数据 | 右侧短标 | 为什么是这个表达 |
|---|---|---|---|
| 聪明 | `benchmarks.eci` | `世界#1` | 名次是排序的直接结果，零加工，不需要读者理解 ECI 的量程 |
| 编程 | `coding[]` 里最合适的一条 | `顶尖` / `很强` | **只能是分位档**，理由见下 |
| 记性 | `contextWindow` | `1M` | 绝对值本身就可比 |
| 便宜 | `pricing.outputPerMTok` | `$50` | 同上，条长取反（越便宜越长） |

**编程那一条为什么不显示分数也不显示名次**，两次试错的结论：

- *原始分数不行*。这个维度被切成了二十多个互不兼容的赛制。并排的三张卡片
  一张写 95.0%（转载的 SWE-bench Verified）、一张写 78.7%（Epoch 复跑）、
  一张写 41.0%（SWE-Bench Pro，中位数本来就低三十多分），读者一定会比大小。
- *名次也不行*。分位池按「赛制 + 测量方」分组后大小从 6 到 85 不等，
  「6 个里第 2」和「25 个里第 2」显示出来都是「榜内#2」。
- *分位档是唯一跨池可比的表达*。原始分数、赛制、测量方、精确名次全部
  留在悬停提示与详情页的「编程战绩（按赛制分列）」里。

厂商自报的成绩在数值后面缀一个 12px 的「自报」——一屏几十张卡片没人会去悬停，
而一个自报的 95 和一个第三方实测的 78 摆在一起不加标注，读者必然得出错误结论。

### 2.2 家具降级为场景

书架和电脑仍然由数据驱动，但不再独自承担传达信息的责任：

- **书架降饱和**（`Bookshelf` 的 `muted`）。满格的彩色书脊比角色本身还跳，
  而「记性」这条横条已经把同一件事说清楚了。
- **空桌不画**。没有编程成绩时原本摆一张问号盖布桌，出现率 79%。
  现在由 `buildVisualPruning` 自校准判定：**任何视觉元素在同屏出现率超过 60%
  就在广场层撤掉**，这是把标签系统的稀有度裁剪（35%）推广到画面本身。
  雾化斗篷、「会用工具」「会深思」图标同理。

这不是删除信息，是让视觉权重与信息量匹配。「编程能力未知」这个事实完全保留，
只是从「占屋内三分之一的家具」变成了能力条上一个带描边的空槽。
等哪天编程覆盖率上去、空桌出现率跌破 60%，它会自动回到屋里——那时它才真的是信号。

三个层次的信息密度递进：

| 层级 | 承载 |
|---|---|
| 屋子外观 | 出生年月、厂商的娘化角色、体型（规模）、能力小物件、房龄、厂商配色与檐口形制 |
| 名牌 | 特征标签、模型名、厂商家徽、能力图标、**四条能力横条**、一句话人设 |
| 角色房间详情页 | 全维度 + 所有原始数值 + 按赛制分列的编程战绩 + 逐字段数据来源 |

### 2.3 广场的布局：先看格局，再看街区

「一目了然」不能靠 39 张等大的卡片平铺——那样读者得自己一张张比。
广场现在分两层：

**首屏「峡谷之巅」冠军横条**（`src/lib/champions.ts` + `ChampionRow`）。
八块领奖台：最聪明 / 最会编程 / 最划算 / 最便宜 / 记性最好 / 最新发布 / 国内最强 / 开源最强。
每块只写一个头衔、一个名字、一个数字、一句为什么。点进来三秒内就知道当下谁在什么位置。
全部由第三方公开数据算出，规则：

| 头衔 | 取值 | 准入门槛 | 为什么要门槛 |
|---|---|---|---|
| 最聪明 | ECI 最高 | 在役 | — |
| 最会编程 | **多榜共识分**最高：在所有第三方编程榜上的平均分位（`coding-consensus.ts`） | 在役，至少参加 3 个够大的榜 | 曾用单一榜单（Epoch 复跑的 SWE-bench Verified，仅 25 个模型）取最大值，结果把头衔颁给了被测得最早的老模型 Opus 4.7，而综合第一的 Fable 5 根本没上那张榜。单榜最大值系统性偏向老模型 |
| 最划算 | 性价比分（见 4.6）最高 | 有 ECI | — |
| 最便宜 | 输出价最低 | **有 ECI** | 没被任何第三方测过的模型再便宜也没有决策价值 |
| 记性最好 | 上下文最大 | 有 ECI | 同上 |
| 最新发布 | 发布日期最近且不晚于今天 | **形象注册表内的厂商** | 否则会被社区微调模型刷屏 |
| 国内最强 / 开源最强 | 各自范围内 ECI 最高 | 在役 | — |

标题旁不放任何解释性文字（试过加「只认第三方实测」和「刚发布待评测：…」两行，用户判为废话）。
口径写在每张卡的悬停提示和详情页里。卡片最窄约 170px，模型名允许折两行、绝不截断。

「最会编程」的共识分同时用于 `persona.ts` 的「最会写代码」和 `traits.ts` 的「编程第一」标签，
三处永远指向同一个模型。

**按厂商实力分街**（`src/lib/roster.ts` 的 `PlazaTier`）。国外、国内各自三条街，整行铺满：

| 街区 | 规则 | 想传达的 |
|---|---|---|
| 王者 | **厂商实力榜**前十（各家最高 ECI 排序） | 这几家在领跑 |
| 星耀 | 参加过第三方评测 | 有据可查的第二梯队 |
| 未定级 | 一次第三方成绩都没有 | 不是差，是还没被测——这是数据缺口，不是能力判断 |

实力按**厂商所有在役模型的最高 ECI** 算，不按广场上展示的那一个——
否则 Anthropic 刚发的 Fable 5.1 因为还没 ECI，会把整家厂商从头部街拽到郊野。
每条街有路牌写明规则（「3 家 · 综合智力全球前十的厂商」），读者不需要猜分组依据。

**屋子下沿的「本家更新」便条**（`Plaza.tsx` 的 `NewerNote` + `roster.ts` 的 `newerThanFlagship`）。
门面按实力选是对的，但它有一个读者能直接察觉的副作用：厂商刚发的型号往往还没拿到
第三方评测分，于是在广场上根本看不见。真实反馈是「DeepSeek V4.1 Flash 不是都发布了么，
为什么没更新」——它其实在站里（详情页、时间线、总表都有），只是没站在屋子里。

便条不改变选拔结果，只把事实说出来并给一条直达的路：`▲ 本家更新：DeepSeek V4.1 Flash`。
触发条件是同厂存在比门面晚至少 `SUCCESSION_MIN_DAYS`（7 天）发布、有核心数据、
且不是服务档别名的在役型号。七天这道门槛是必需的：上游同一模型常有多条别名记录，
发布日期差一两天，不设门槛几乎每间屋子都会挂上这行字。

实测覆盖 40 间屋子里的 7 间（18%），远低于视觉剪枝的 60% 红线，所以它是高信噪比的。
这个比例会随上游评测进度浮动，用 `npx tsx scripts/qa/newer-than-flagship.ts` 复查。

便条做成屋子的**兄弟节点**而不是名牌里的一行：整间屋子本身是一个指向门面的链接，
链接里不能再嵌链接。

「头部」的门槛曾是「厂商最强模型在**模型级**全球榜进前十」。OpenAI 一家占了前十的七席，
头部街只剩四家，国内只有月之暗面——智谱 GLM-5.3 排全球第 15 左右被挡在门外，
用户看到的是「国内头部怎么只有一个」。读者比的是厂商，门槛就该在厂商之间划。

**国外 / 国内分区上下堆叠，两块永远都在。**
布局走过四版：左右两栏（右栏第二屏就空了，一半宽度浪费）→ 揉进同一条街用旗子区分
（空间用满了，但用户要求分开展示：「国内现在什么水平」是一个独立问题，要整块地看）→
上下堆叠 + 一条贴顶的「全部 / 国外 / 国内」标签栏 → 现在这版，标签栏撤掉。

标签栏被撤是因为**它是个筛选器而读者要的是跳转**：点「国内」会把国外整块藏起来，
代价是首页唯一的客户端状态、一条常驻遮挡的浮条、以及「我现在看到的是不是全部」的疑惑。
换成页顶那排锚点（`PageJump.tsx`）之后，四个区一键直达、两块内容都在、零 JavaScript。
教训：**「我想看那一段」不等于「我只想看那一段」**，前者用锚点，别用筛选器。

`PageJump` 放在内容区第一行：读者从顶栏往下扫，第一眼就知道这页有什么。
样式刻意压低——平时是几乎看不见的灰边，悬停才亮成该区识别色，
它是索引不是主导航，不该和顶栏那三个像素按钮抢注意力。

**配色**（`globals.css` 的 `@theme`）。第一版整站是紫罗兰调（`#2a2148` / `#5b3f7a`）加粉红「国内」色，
紫色饱和度高、明度低、铺满整屏，是最容易看累的组合。第二版把夜空、石板、屋墙全部统一到
**同一族低饱和深蓝灰**，只让金色标题、厂商色屋顶和四条能力条带颜色。
屋墙按房龄分五档只在明度上拉开（`--color-wall-*`），地板与名牌再深一档做出剖面层次。
所有颜色都在 CSS 变量里，组件里不再出现十六进制色值。

**字号**：第三次整体上调一档——正文 13→14，卡片小字 10/11→12，名牌 13→14，屋子随之放宽到 222px
（1440 视口下正好六间一行）。用户的原话是「阅读舒服是最重要的」；游戏感来自画、边框和动画，不来自小字。
**页面壳**（`.page-shell`，`globals.css`）：首页顶栏与正文共用，`max-width: 1512px`，
两侧内边距 16 / 32 / 48px（sm / xl）。1512 是算出来的：减去 xl 的 96px 内边距是 1416，
再减广场自己的 24px，屋子轨道正好 1392 = 六间 222px 的屋子加五条 12px 的沟。
早先是 1600 且顶栏另用一套内边距，结果宽屏上导航贴着屏幕右边、内容却居中，
角色一路铺到屏幕边缘而右侧空一大条。**顶栏和正文必须用同一个壳**，这是宽屏第一眼就能看出的毛病。

**科技感的边界**：只加在框线、角标、小灯上，一格都不进内容区。现在有四处——
① HUD 状态读数（细青边 + 半透底 + 呼吸小灯，像一台联机中的仪器）；
② 首页四个大块共用的 `SectionFrame`：顶边一条识别色 + 两端下垂短线 + 底部两角 L 折角；
③ 同一条顶边上一道 2px 带辉光的扫光缓慢滑过，各区错开相位（`hud-sweep`，9s）；
④ 天际线高楼顶上的红色航空警示灯，各自错拍慢闪。
反面教材是撤掉的那批：整页 CRT 扫描线、冠军卡各自的霓虹顶线、地面石板缝网格——
用户原话「网格深色背景很干扰阅读」。规律重复的线条压在文字后面，眼睛会不自觉去追，
无论透明度多低。教训：**正文后面的背景必须是平的**，地面感交给天空下那条草皮带去给；
想要科技感就往边框和背景深处加，那里离字最远。

**「已退役」页撤掉**。退役模型在排行榜「含已退役」筛选、厂商页和详情页里都能看到，单独一页对读者没有增量信息，
只多一个入口。导航从四项减到三项。**时间线**同轮改版：模型从 12px 纯文字改成带底色、边框、厂商徽记的 14px 牌子，
月份标题用像素字 `2026.08`——几百个名字连成一片时，牌子的边界就是眼睛的分隔符。

## 三、屋外可见的信号

### 3.1 体型 ← 模型规模

**档位是分位数而不是绝对阈值。** 这一点经过两次失败才定下来，过程值得记录，
因为它同时解决了一个视觉问题和一个「三年后悄悄烂掉」的问题。

最初的方案是写死的绝对阈值（参数量 < 10B / 10–50B / … 、价格 < $0.5 / $0.5–2 / …）。
实测下来当代旗舰模型的定价高度聚集，绝对阈值把它们全部塞进了同一档——
广场上所有大厂角色一样高、穿一样的衣服，这个视觉维度等于不存在。
第二次改成价格分位数，但因为闭源模型的档位是「价格档 × 命名档」的加权平均，
**平均永远会向中位数回归、压缩值域**，结果仍然全部落在第 4 档。

最终方案：先给每个模型算一个 0–1 的连续规模分，再对**全体模型的分数**做五等分。

| 模型类型 | 规模分 |
|---|---|
| 开源且有确切参数量 | `log10(总参数量)` 在全体开源模型中的分位 |
| 闭源但有定价 | `0.75 × log10(输出单价)的分位 + 0.25 × 命名分` |
| 两者皆无 | 仅命名分 |

命名分：`nano/mini/flash/lite/small` → 0，无后缀 → 0.5，`pro/max/ultra/opus/large` → 1。

这样五个档位在构造上一定都有人，广场必然呈现明显的高矮差异。
代价是档位表达的是**「在当前这批模型里算大还是算小」**而不是绝对参数量。
对一个展示「当下格局」的站点来说，这个相对语义反而更贴近用户真正想问的问题，
而且它**自校准**：若干年后模型普遍变大、token 价格普遍下降，档位分布依然成立，
不会像绝对阈值那样在没人维护的情况下整体失真。

MoE 模型按**总参数量**计分，激活参数量在第三层的属性面板单列。

**闭源模型拿不到参数量**——实测 Epoch 数据库里 OpenAI 覆盖率 3%、Anthropic 0%，
而且训练算力估计同样是零覆盖，所以「参数量拿不到就用 FLOP 顶上」这条路也是死的。

**所有估算档位的角色一律加一件雾化斗篷**，鼠标悬停显示「体型为估算值，官方未公布参数量」。
这既是诚实标注，也让「神秘的斗篷已成为大厂默认皮肤」本身成为对行业现状的一句评论。

- 数据源：开源走 Hugging Face `safetensors.total`（`confidence: exact`）；闭源走上式合成（`confidence: estimated`）。
- 实现：`buildSizeScale()`，见 `src/lib/derive.ts`。

## 四、自动特征标签

**这是让普通人一眼 get 到差别的主力。** 像素形象能表达的差异有限，
而「全球最强」「白菜价」「刚出生」这类人话，比任何视觉隐喻都好懂。

每间屋子挂 1~3 块，全部由数据算出——**谁符合谁挂、不符合就摘**：
排名掉出前十，「十强」当天消失；发布满 30 天，「刚出生」自动过期。

| 色调 | 含义 | 例子 |
|---|---|---|
| 金 | 榜首类 | 全球最强、五强、十强 |
| 绿 | 好消息 | 白菜价、性价比之王、刚出生、开源 |
| 蓝 | 能力 | 编程第一、记性最好、百万记性、会深思 |
| 红 | 贵 | 天价 |
| 灰 | 老与退役 | 元老、已退役 |

**稀有度裁剪**：一块标签在同屏模型里出现率超过 35% 就自动剪掉。
「百万记性」在旗舰模型里几乎人手一块，满屏挂着等于没挂。
只有「全球第一」「已退役」这类天然稀有的永远保留。这同样是自校准的——
等哪天百万上下文重新变成稀罕事，这块标签会自己回来。

实现见 `src/lib/traits.ts` 的 `assignTraits()`。

### 4.5 一句话人设：限定域最高级

标签回答「它有什么标签」，横条回答「它多强」，但读者真正想问的是
**「所以我该拿它干嘛」**。卡片最下面那一行负责回答这个。

机制是**从宽到窄找出「这个模型在哪个范围里是第一」**：枚举
「维度 × 限定域」的全部组合，只保留该模型排第一的，然后先按维度重要性、
再按域最宽挑一条，套成一句话。

- 维度（按重要性）：综合智力最强 → 最会写代码 → 记性最好 → 最划算 → 最便宜
- 限定域（按从宽到窄）：全世界 → 开源模型里 → 中国厂商里 / 海外厂商里 →
  百万上下文的模型里 → 看得懂图的模型里 → 十强里

产出的句子例如：「全世界综合智力最强的模型」「开源模型里综合智力最强的模型」
「十强里最划算的模型」「中国厂商里最会写代码的模型」。

三个容易搞反的地方：

1. **域要从宽到窄，不是从窄到宽。** 直觉上「域越窄越具体越好」，
   但对全球第一的模型来说「百万上下文的模型里综合智力最强」
   远不如「全世界综合智力最强」有力。要找**站得住的最宽说法**。
2. **域必须有下限**（当前 5 个成员）。在只有两个成员的圈子里当第一毫无信息量。
3. **生硬来自泛化，不来自模板。**「一款性能优秀的大语言模型」对谁都成立，
   所以对谁都没用。而「在某个域里排第一」这个条件从结构上保证了
   同一句话在全站最多属于一个模型。

三级兜底，绝不留空也绝不编造：一级是限定域最高级；二级是纯事实拼接的定位式描述
（「便宜、能读长文、会看图的开源模型」）；三级老实说「上游只收录了它的基本信息，
还没有公开的评测成绩」。

全程不调用任何 LLM。实现见 `src/lib/persona.ts`。

### 4.6 性价比的算法，以及它曾经错在哪

「性价比之王」这块标签第一版算的是 `eci / outputPerMTok`。**这是错的**，
而且错得很隐蔽：比值型指标在分母趋近于零时会爆炸。实算前三名是
Llama-3.1-8B（$0.08，ECI 115 → 1441）、Mistral Nemo（789）、GPT OSS 20B（684），
而 Claude Fable 5 只有 3.25。于是这块牌子永远颁给最便宜的那批，
而不是「又好又省」的那批——和它想表达的意思正好相反。

现在改成**两个分位相减**：智力分位减价格分位，两个都是 0~1 的无量纲量，
差值落在 -1~1 之间，不会爆炸，也不需要任何可调参数。修完之后第一名是
DeepSeek V4 Flash（$0.28，ECI 154.3），这才是这块牌子该有的样子。

实现见 `src/lib/derive.ts` 的 `buildValueScore()`。

进入房间后，模型的每一项能力都由一件家具承载。

| 家具 | 数据字段 | 档位划分 | 数据源 |
|---|---|---|---|
| **电脑** | SWE-bench 系列 | 无数据 → 盖着防尘布加问号<br>其余按**同赛制内的四分位**分四档：老式 CRT / 笔记本 / 双屏工作站 / 多屏黑客洞 | Epoch + models.dev |

| **稿纸堆** | `maxOutput` | 厚度五档 | models.dev |
| **墙上日历** | `knowledgeCutoff` | 停摆在知识截止日期那一天 | models.dev |
| **黑板** | AIME + GPQA Diamond + ARC-AGI-2 | 公式密度随分数递增 | Epoch |
| **门口队伍** | 真实调用热度 | 排队小人数量 | 待定，见「已知缺口」 |
| **墙角冰箱** | `capabilities.promptCaching` | 支持则出现（存记忆用） | models.dev |
| **围墙与门禁** | `openWeights` | 开源无围墙大门敞开，闭源有围墙 | models.dev |
| **属性面板** | 全部 | 所有原始数值 + 逐字段的数据来源链接 | `provenance` |

属性面板必须逐字段标注来源，这是这个网站区别于「又一个模型排行榜」的地方——
任何一个数字都能点开看它从哪来、什么时候抓的、可信度如何。

**电脑档位不能用写死的分数阈值。** 原先的 30/50/70 是照着 SWE-bench Verified 校准的
（中位数 75.7），而 SWE-Bench Pro 被 Scale 官方测出来的中位数只有 41.0——
同一个模型换个测评脚手架能差二三十分，套用同一把尺子会把被 Scale 测过的模型系统性压低一到两档。
现在按**每个赛制在自己人群里的四分位**计算，跨赛制的分数从此不再相遇。

### 5.1 模型类型：一个词回答「这是个什么模型」

名牌上、总表里、筛选条上都有一个「类型」，取值六种，每个模型恰好落进一种：

| 类型 | 判定（只看 `modalities`，按此顺序） | 2026-09 快照数量 |
|---|---|---|
| 图像生成 | 输出含 image | 16 |
| 视频生成 | 输出含 video | 5 |
| 全模态 | 输入含 audio **且** 含 image / video | 42 |
| 语音 | 其余输入或输出含 audio（识别、合成、只听不看的对话） | 15 |
| 视觉 | 输入含 image / video，输出文字 | 229 |
| 文本 | 只剩文字 | 221 |

为什么不按名字、不按厂商宣传归类：名字里带「Omni」的不一定能听，
带「VL」的也有厂商顺手加了音频输入。`modalities` 是 models.dev 与网关逐字段核对过的，
是这个站唯一能站住的依据。上游偶有把「深度研究」产品的输出标成含图（报告里带图表），
它们会落进「图像生成」——那是数据源的说法，本站不替它改口。

实现在 `src/lib/kind.ts`，文案在 `i18n.ts` 的 `kind`。筛选条上的类型按钮只列快照里真有的类型，
后面跟数量，悬停显示判定依据；URL 参数 `kind=`。

**首页「按类型看」**（`KindRow.tsx`）：峡谷之巅之下、广场之上的一排六张卡，一张一类，
卡上是类型名、在役数量、三个代表模型的小人（有 ECI 的按分数挑，没有的按发布日期挑，同名去重），
点开进总表的该类筛选。为什么不做成广场的筛选：广场只住各家的当家门面，门面必然是对话模型
（`couldBeFlagship` 排除了只出图、只出声的），「图像生成 / 视频生成 / 语音」在广场上永远是空的，
一个点了没东西的筛选按钮比不加更糟。这排卡片是这三类模型在首页唯一的露脸机会。
外框与「峡谷之巅 / 国外 / 国内」同构，识别色用 `--color-dawn`，不与金色抢眼。

### 5.2 搜索：名字、厂商、能力，三件事一个框

**要解决的三个「找不到」**。产品负责人的原问是「我想知道智谱有没有多模态模型」，
用改版前的站走一遍就能看出问题在哪：

| 痛点 | 改版前 | 现在 |
|---|---|---|
| 找某个模型 | 全站没有搜索框。顶栏 → 排行榜 → 页内找到「全部模型」入口 → 才有搜索框，三跳 | 导航条输入名字直达房间 |
| 找某类模型 | 首页「按类型看」六张卡能进，但六类是互斥的，「多模态」无处落脚 | 搜「多模态」给出 321 个并直通筛好的总表 |
| 某家有没有某类 | 厂商页只有一排小人和名次，一个字不提模态；靠名字猜也不行——全站 **89%** 的视觉模型名字里既没有 V 也没有 VL | 搜「智谱 多模态」直接算出 5 个；厂商页顶部也有类型摘要 |

**搜的是三种东西**：模型名（含 slug）、厂商名、以及**能力概念**。
前两种是字符串匹配，第三种不是——「多模态」「开源」「国内」在数据里没有对应字段，
是从 `modalities`、`openWeights`、厂商归属现算的。所以概念命中给出的是
**一个筛选链接加一个真实数量**，而不是一段说明文字：数字点进去必须和总表上的数字一致。

**词能组合**，这是这套搜索唯一有点巧思的地方。查询按空格切开，每个词试着解释成
一个概念或一个厂商；全部解释得通就合成一条结果。「智谱 多模态」→
`?vendor=zhipuai&kind=multimodal` → 5 个。「国内 开源」→ 79 个。
每个维度（类型 / 开放 / 地区）最多取一个，外加至多一个厂商。
之所以值得做：「某家有没有某类模型」是这个站被问得最多的问题形态，
它恰好是一次输入能表达、却要四五步点击才能查出来的东西。

**「多模态」是一个跨类的筛选档，不是第七种类型**。`kind.ts` 的六类必须保持互斥，
否则「每个模型恰好落进一类」这个不变量就没了；多模态只活在筛选层（`filters.ts` 的 `Kind`），
含义是「除纯文本以外的全部」。上游没标模态的模型**不算**多模态——宁可漏，
也不要把「没数据」说成「有能力」。

**索引按需加载**。导航条在 580 个静态页面上都有，把 52 KB（gzip 9 KB）的索引
内联进每一页是不划算的；现在是聚焦搜索框才去拉 `/search-index.json`，整站只拉一次。
禁用 JavaScript 时输入框整个不渲染——一个点了没反应的框比没有更糟，
那种情况下总表页自带的搜索框仍然能用。

**厂商页的类型摘要**（`/vendor/<id>/`）：页头下面一行「多模态 5 · 文本 12 · 视觉 5」，
每格链到总表筛好的名单；每个小人的名牌上再补一行类型标签。
这是从「点小人进厂商页」这条最直觉的路径上回答同一个问题——
搜索解决的是知道要搜什么的人，摘要解决的是顺着页面点进来的人，两条路都得通。

**搜索框在导航三个按钮的左边**，不在右边。它是入口里最宽的一个，
放右边会让导航条随关键词长度忽长忽短；而且读者的阅读顺序从左开始，
「先想去哪，找不到再点固定入口」。

### 5.3 同系列历代：这一代在哪

详情页名牌正下方一条时间轴，左旧右新，当前这一代描金边。每格三样：发布月份、名字、ECI。
分数放在这里才有意义——同一条线、同一种类型的模型，ECI 之间是可比的，
一眼就能看出哪一代是真跨越、哪一代只是小改。

**判定规则一句话**：同一厂商 + 名字里第一个数字之前那一段相同 + 类型相同（`src/lib/lineage.ts`）。
版本号的位置是产品线命名里唯一稳定的结构，「GLM-5.3」「Claude Fable 5.1」「Qwen3.8-Max」
的数字前面恰好都是这条线的名字。

试过更聪明的做法，失败了：把 Flash / Pro / Mini 这类档位词也剥掉之后，
OpenAI 一家 55 个模型全成一族，GPT-3.5 和 GPT-6 Astra 排进同一条时间轴——
那不是产品线，是清单。加上「类型相同」这一刀，GLM 的文本线（13 个）与视觉线（5 个）
自然分开，全库 76% 的模型因此有了至少一个同系列邻居。

**仍然认不出来的**：OpenAI 用代号（Luna / Sol / Terra / Astra）而不是纯数字区分并行款，
所以「gpt / 视觉」一族有 46 个。对超长家族开一个以当前模型为中心的七格窗口，
并如实写出「共 46 个 · 这里是相邻的 7 个」，不假装那是一条干净的线。
七格是量出来的：详情页正文宽 1152，减去内边距剩约 1064，七格 124px 加六个箭头正好摆得下；
放到九格当前这一代会被挤出右边缘，而「当前在哪」正是这条时间轴存在的理由。

窄屏折成两列而不是横向滚动：滚动条会把高亮的当前格推到屏幕外，读者不知道要往右拨。

### 5.4 厂商页：时间轴，不是年份箱

厂商页早先按年分组、组内按综合智力降序——一整年的模型堆成一坨，顺序还是按分数排的。
用户的原话是「只能看到发布区间，看不到具体时间线和先后顺序」。现在按**发布月份**分组、
新的在上、组内也按日期倒序，左侧一条轴、节点大小随当月发布数量变化（与「时间线」页同一套视觉）。
每个小人名牌上补一行 `08.14 · 文本`：日期回答先后，类型回答是什么。
面板用 `w-fit`——一个月常常只发一两个，铺满整行的空面板看着像出错了。

月份是验证过的粒度：厂商月份组数的中位数是 3，最多的 OpenAI 28 组。28 组是长，
但那本来就是一条 28 个月的时间线。

### 5.4.1 内页也要有天空：统一页头与 HUD 外框

首页有一整条黎明天际线、四块带角标和扫光的 HUD 外框；内页（时间线 / 排行榜 / 总表 /
厂商页 / 详情页 / 素材署名）却只有一排居中浮着的导航加一片纯色底。读者的原话是
「背景太素，显得页面很单调」「顶部导航栏的布局也很怪」——怪在三处：没有站名、
没有回首页的入口、导航居中而正文左对齐，两者对不齐。

`SiteHeader.tsx` 把首页那套页头收成一个组件给所有内页用：
**窄一档的天空带**（首页天际线 48~78px，这里 30~50px——内页的主角是表格和时间轴，
天空只负责证明「还在同一个世界里」）+ 站名（兼回首页入口）+ 导航 + 草皮线，
宽度跟正文共用 `page-shell`。内页正文也从 `max-w-6xl`（1152）放宽到 `page-shell`（1512），
两侧那两条无所事事的空白收窄了一半。

**内页的主内容不套 `SectionFrame`。** 试过一版给时间线、排行榜、总表、厂商页各套一个
带识别色顶边的外框，当场被否：「不要拿边框把时间线内容主体部分括起来」。
原因不难理解——首页那四块是**并列的分区**，外框是用来把它们彼此分开的；
内页只有一块内容，给唯一的东西画个框不是分区，只是多一道线。
页头那条天空带已经足够把「素」解决掉了。

### 5.5 B 站实测视频

详情页最底下一块卡片墙，最多 12 条：封面、标题、**UP 主**、时长、发布日期、播放量，点开进视频。
数据是离线抓的——B 站公开搜索接口按「{模型名} 测评」搜一遍，结果提交进仓库。
不能在浏览器里现搜（没开 CORS，而这是纯静态站），也不该放进构建期（一轮 200+ 请求，
等于把发版成功率押在别人的风控策略上）。

**搜索结果不能直接用。** 搜「DeepSeek V4 Pro 测评」，前几条里混着「DeepSeek 开发指南」
「深夜宕机，天才程序员的陨落」这类沾边不对题的。所以过一道和站内其它地方同源的严格规则：
**标题里必须出现这个模型的名字**。放宽过一次到「系列词干」，立刻把「Claude Code 封号原因被曝光」
挂到了 Claude Fable 5 上——在一个把「每个数字都要有出处」写进原则的站里，
给一个模型挂一条讲别的东西的视频，比这块空着糟得多。

**排序是站长置顶 + 播放量降序**，不用 B 站的相关性顺序：那个顺序说不清，
而播放量是卡片上就印着的数字，读者能自己判断排得合不合理。
每张卡都印 UP 主名字，站长自己的视频额外打一个「站长」标——**这些是站外用户的作品，
不是本站的评测结论，谁做的必须一眼可见**。底下一行小字写明口径与免责。

覆盖范围是「在役 且（综合智力前 120 或 180 天内发布）」共 231 个模型，其中 116 个搜得到。
门槛第一版定成「前 60 / 120 天」，结果把 DeepSeek V4 Pro 漏在了外面（ECI 排 61、发布 146 天，
两条线各差一点），而它有一条 41 万播放的实测——**门槛卡在「刚好漏掉知名模型」的位置就是定错了**。

这一块同时是「做成 B 站 Toy」的落点：在 Toy 容器里点卡片走 `toy.navigate` 原生打开播放页，
Toy 自己留在后台，不会把人顶出去。

## 六、角色形象：每家一个固定的娘化角色

### 6.0 为什么从 LPC 换成手绘娘化形象（2026-09-26）

第一版角色由 LPC 分层素材按哈希拼装：头型、发型、衣服都是从素材池里抽的。
用户的反馈是**「具有随机性」**——同一家的模型之间、不同厂商之间，看不出任何「这就是 DeepSeek」的线索。
根因是 LPC 只有人类、蜥蜴、兔子、兽人这几种头型，DeepSeek 只能是一只蜥蜴，Anthropic 只能是一只老鼠。

现在的做法：**每家厂商一个固定的 Q 版像素娘化角色**，同一家的所有模型共用。形象的优先级是：

1. **社区里已经流传开、读者一眼认得的娘化形象**：DeepSeek 鲸鱼娘（银白长发、鲸鱼发饰、鲸尾），
   linux.do「AI娘们的互动小剧场」里的 GPT 酱、GPT Image 娘、Claude 娘、Gemini 娘，Z.ai 黑狐娘；
2. **官方形象**：豆包自己的 3D 女孩、xAI 在 Grok 里推出的二次元形象 Ani；
3. **按图标设计**：没有公认形象的厂商，把 logo 做成发饰、品牌色做成发色和衣服，再加一个好记的特征
   （Meta 羊驼耳、Mistral 贝雷帽、腾讯企鹅配红围巾、百度熊耳、美团猫耳、蚂蚁触角、Perplexity 圆眼镜）；
4. **兜底**：未收录的厂商也是固定形象——发色取品牌色（没有品牌色时按厂商 id 固定取一个色相），
   发饰是厂商首字母，发型和衣服按厂商 id 固定选一套。永远不会缺图，也永远不随机。

两条产品线单独成角：OpenAI 的出图模型是 GPT Image 娘，Google 的 Gemma 系列是 Gemma 娘（`VARIANTS`）。

**风格要求是「电子宠物 + 王者荣耀英雄」**：大圆头、短胖身体、大眼睛带两颗高光、张嘴笑、腮红；
同时每位英雄披着金边披风、肩甲与金腰带，脚下踩一圈半透明金色光环，手握一把看家武器
（剑 / 法杖 / 长枪 / 弓 / 折扇 / 枪 / 三叉戟 / 战锤 / 匕首 / 盾 / 法典 / 麦克风 / 能量光刃，
分配表见 `designs.ts` 的 `WEAPONS`）。
第一版画成了约 2.3 头身的普通 Q 版，被判「眼睛太丑」，改成现在的比例。
Gemini 的星星必须是新 logo 的四色（上红、右蓝、下绿、左黄，白边），画成蓝紫渐变被指出过。

### 6.1 怎么画的

全部是字符画 + 程序填色，代码在 `scripts/sprites/chibi/`，**不调用 AI 生图，不依赖外部美术素材**：

| 文件 | 内容 |
|---|---|
| `designs.ts` | **人类常识层之五**：厂商 → 角色设定表（发色、发型、眼色、服装、发饰、兽耳、尾巴、配件、武器），附形象依据 |
| `body.ts` | 共用的身体、脸、手臂、九种服装，以及披风、肩甲、金腰带、金色光环 |
| `hair.ts` | 七种后发 + 四种刘海，由轮廓线程序化填充和打阴影 |
| `extras.ts` | 兽耳、尾巴、眼罩/墨镜/贝雷帽/围巾/触角/眼镜/铃铛、四样能力小物件、26 个厂商标志的像素改写 |
| `weapons.ts` | 13 种英雄武器（剑 / 法杖 / 长枪 / 弓 / 折扇 / 枪 / 三叉戟 / 战锤 / 匕首 / 盾 / 法典 / 麦克风 / 能量光刃），钢 + 金配件 |
| `grid.ts` / `color.ts` | 字符画 → 像素（每层自动描边）、五阶色板（阴影偏冷、高光偏暖）、GOLD 金色板 |
| `render.ts` | 设定 + 能力标记 → 9×5 格精灵表与叠加层锚点 |
| `review.ts` | `npm run sprites:review`，出人工校验稿：`docs/samples/chibi-review.html`（带说明，不入库）与总览截图 `chibi-review.png`（入库留档） |

精灵表沿用原来的 9 列 × 5 行布局，前端一行不用改：第 0 行是站姿，
第 1–4 行是同一段九帧循环（轻微上下浮动 + 眨一次眼）。角色只画正面，所以四个「行走方向」行内容相同。

**改形象的工作流**：改 `designs.ts` → `npm run sprites:review` 看校验稿 → `npm run sprites` 重出全站。
借用了社区或官方形象的条目，要同步改 `/credits/` 页（`src/app/credits/page.tsx`）里的出处列表。

### 6.2 家徽

名牌上 12px 的位置放不下小人，厂商身份在名字旁边由一枚 12×12 的像素家徽承载，
字符画定义在 `src/data/crests.ts`，母题取自 `vendor-registry.ts` 的 `motif`。
排行榜、时间线这些没有角色的地方也靠它认人。未收录厂商回落到 `wanderer`。校对页 `/qa/crests`。

## 七、形象的确定性

没有任何随机数：角色由厂商 id 查表决定（未收录厂商由厂商 id 的哈希固定选一套），
能力小物件由模型数据决定。全程离线，同一输入永远产出同一字节，606 张精灵图全量约 7 秒。

## 八、排版规则

**像素字体只用于站名与纯拉丁/数字**：模型名（`Claude Fable 5`）、名次（`#1`）、
门楣日期（`2026.06`）。这些本来就是拉丁字母和数字，像素风正好。

**所有中文一律用系统无衬线体，最小 12px。**

中文像素字在 12px 以下笔画会粘连，读一两个词行、读一段话很费劲。
这一点走过弯路：第一版把中文也交给了像素字体，标签牌尤其难认，被反馈了两次。

游戏感应该来自像素画、硬边框面板、配色和动画，**不该靠让字变难认**。

字体是 Fusion Pixel Font（OFL-1.1，商用免费）。
注意 Zpix **不是**开源字体，商用授权 ¥7000 且明文禁止「拆分」——网页子集化恰恰就是拆分。

## 九、已知缺口

诚实列出做不到的部分，不用视觉元素掩盖数据的缺失。

**视觉理解只有布尔值。** MMMU 无官方机器可读源、Epoch 未收录、AA 不可用，所以眼镜没有度数之分。

**闭源模型的规模是估算值。** 参数量与训练算力在闭源厂商处都是零覆盖，雾化斗篷会是大部分旗舰角色的默认皮肤。

**速度维度不存在。** 唯一数据源 Artificial Analysis 禁止再分发，已整体砍掉。

**「门口队伍」的数据源尚未确定。** 真实调用热度目前只有 OpenRouter 的使用量排名，
而 OpenRouter 的 ToS 禁止自动化抓取，法律上是灰区。若最终无合规来源，这件家具会撤掉而不是拿别的数字凑。

**部分模型是单源数据。** 例如某些厂商的专用模型只有 OpenRouter 收录，models.dev 和 LiteLLM 都没有。
这类模型会在属性面板标注「单源数据，未经交叉校验」。
